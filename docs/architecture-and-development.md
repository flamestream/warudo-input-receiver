# FS Input Receiver: Architecture & Development Guide

This guide details the technical architecture, development workflows, and extension mechanisms for the **FS Input Receiver** Warudo plugin.

---

## 1. System Overview

**FS Input Receiver** is a Warudo plugin (`FlameStream.PointerReceiver`) that connects Warudo 3D avatars and scene props to real-world input hardware (mouse, graphics tablets/pens, keyboards, gamepads, steering wheels, and flight sticks) via high-speed UDP streams generated by **FS Input Device Emitter**.

```
┌─────────────────────────────────────────────────────────┐
│              Hardware / Windows OS                      │
│ (Wacom Tablet, Mouse, Keyboard, Xbox/PS/DirectInput)   │
└──────────────────────────┬──────────────────────────────┘
                           │ Low-level Windows Hooks / APIs
┌──────────────────────────▼──────────────────────────────┐
│           FS Input Device Emitter (C++)                │
│    (FsInputEmitter.exe + Mouse/Keyboard DLLs)          │
└──────────────────────────┬──────────────────────────────┘
                           │ UDP Packets (Ports 40610 - 40614)
┌──────────────────────────▼──────────────────────────────┐
│           Warudo Application Context                     │
│ ┌─────────────────────────────────────────────────────┐ │
│ │  FS Input Receiver Plugin (FlameStream.PointerReceiver)│ │
│ │  ├── ReceiverAsset (Background UDP listener tasks)  │ │
│ │  ├── PointerReceiverAsset (Mouse/Pen screen mapping)│ │
│ │  ├── InputReceiverAsset (Gamepad/Wheel animators)   │ │
│ │  └── Warudo Graph Nodes (Triggers, Animators, Logic)│ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## 2. Plugin Structure & Registrations

The entrypoint is [`src/PointerReceiverPlugin.cs`](file:///d:/Code/FS%20Input%20Receiver/src/PointerReceiverPlugin.cs). It uses Warudo's `[PluginType]` attribute to declare:
- **`AssetTypes`**: Persistent objects added to the Warudo hierarchy (scene assets with inspector properties and update loops).
- **`NodeTypes`**: Visual scripting nodes accessible in the Warudo blueprint/node editor.

### 2.1 Asset Types (`src/Assets/`)
1. **`ReceiverAsset`** (Base class):
   - Opens a `UdpClient` on a background thread (`Task.Run(() => Listen(udpClient))`).
   - Receives packets into `lastState` string safely.
   - Validates incoming protocol headers (`CheckValidProtocolVersion`).
   - Exposes port and connection status in the Warudo UI.
2. **`PointerReceiverAsset`**:
   - Manages mouse and drawing tablet inputs.
   - Converts 2D screen coordinates to 3D tablet surface positions.
   - Animates avatar body posture, arm kinematics, and held props (pens, styluses).
3. **`KeyboardReceiverAsset`**:
   - Parses 256 virtual key codes (`VK_...`) from bitset packets.
   - Exposes key queries to blueprint nodes.
4. **`InputReceiverAsset`** (and subclasses `DirectInputReceiverAsset`, `GameInputReceiverAsset`, `XInputReceiverAsset`, `GamepadReceiverAsset`):
   - Normalizes thumbstick axes, triggers, D-pads, and buttons.
   - Drives character finger poses and button press animations using **Animancer** layers and bone transforms.
5. **`DrawingScreenAsset`**:
   - Defines physical/virtual drawing screen boundaries and visual setups.
6. **`VisualSetupAnchorAsset`**:
   - Provides anchor points for placing controllers, keyboards, and props in 3D scene space.

### 2.2 Node Types (`src/Nodes/`)
- **Data Getters**: `GetPointerReceiverDataNode`, `GetKeyboardReceiverKeyNode`, `GetGamepadReceiverDataPs5Node`, `GetGamepadReceiverDataXbox360Node`, `GetGamepadReceiverDataSwitchNode`.
- **Event Listeners**: `KeyboardReceiverOnKeyDownNode`, `KeyboardReceiverOnKeyUpNode`, `InputReceiverOnButtonDownNode`, `InputReceiverOnButtonUpNode`, `InputReceiverOnSwitchChangeNode`.
- **State Checkers**: `KeyboardReceiverIsKeyDownNode`, `InputReceiverIsButtonDownNode`, `GamepadReceiverIsButtonDownNode`.
- **Animators & Trackers**: `GamepadHandTrackerNode`, `GamepadButtonHandAnimatorNode`, `GamepadButtonPropAnimatorNode`, `GamepadDPadHandAnimatorNode`, `GamepadStickHandAnimatorNode`, `GamepadStickPropAnimatorNode`.

## 3. Development & Hot-Reload Workflow

Warudo supports on-the-fly compilation through the **Warudo Playground** feature. When files inside `Warudo_Data/StreamingAssets/Playground/` are updated, Warudo compiles them dynamically and reloads the plugin.

### 3.1 Synchronizing Code
The repository includes automated mirroring tools in `personal-tools/`:

```cmd
# Push changes from repo to Warudo Playground (Hot-Reload)
sync.bat src warudo

# Pull changes from Warudo Playground back to repo
sync.bat warudo src

# Preview changes before copying
sync.bat src warudo --dry-run
```

### 3.2 Pre-Sync Compilation Check
Before pushing to Warudo, compile locally to catch syntax or type errors:
```powershell
# From personal-tools/
.\verify-build.ps1

# Or with automatic sync upon success:
.\verify-build.ps1 -Sync
```

## 4. Warudo SDK Core Concepts & Guidelines

### 4.1 Asset Lifecycle
- `OnCreate()`: Initialize default parameters, register watchers with `Watch(nameof(Field), ...)`.
- `OnUpdate()`: Executes every frame. Read `lastState`, update bone transforms, broadcast port values.
- `OnDestroy()`: Clean up background tasks, close UDP sockets (`StopReceiver()`), destroy tween animations.

### 4.2 Thread Safety in UDP Listener
Warudo runs its update loops and Unity engine calls on the main thread. The UDP listener task runs on a background worker thread.
- **Rule**: Never call Unity APIs (`Transform`, `GameObject`, `Mathf`, `Toast`) directly from the `Listen()` thread.
- **Pattern**: Write incoming data to `lastState` string in `Listen()`. Parse `lastState` on the main thread inside `OnUpdate()`.

### 4.3 Node Conventions
- Use `[NodeType(Id = "...", Title = "...", Category = "...")]` to register nodes.
- Use `[DataInput]` and `[DataOutput]` for data pins.
- Use `[TriggerInput]` and `[TriggerOutput]` for execution flow pins.

### 4.4 Localization
All user-facing strings must use localization keys:
- Keys are defined in JSON under `src/Localizations/`.
- Access localized strings in code via `"KEY_NAME".Localized()`.

## 5. Managed Assemblies Reference

Warudo provides pre-loaded assemblies located in `Warudo_Data/Managed/` that plugins can reference:
- `Warudo.Core.dll` & `Warudo.Plugins.Core.dll`: Warudo plugin architecture, node graphs, asset systems.
- `UnityEngine.CoreModule.dll`, `UnityEngine.AnimationModule.dll`, `UnityEngine.XRModule.dll`: Unity 3D engine APIs.
- `Animancer.dll`: Layered animation control for skeletal meshes.
- `DOTween.dll`: Procedural tweening and smoothing.
- `UniTask.dll`: High-performance asynchronous tasks for Unity.
- `websocket-sharp.dll`: WebSocket communication.
- `Newtonsoft.Json.dll`: JSON serialization.
